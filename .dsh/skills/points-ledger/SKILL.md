# 积分商城记账（points-ledger）

把用户的一句话变成一条流水文件，并回报积分与升级进度。**网页是只读的，你是唯一写入方。**

完整规则文档：项目内 `docs/schema.md`（数据 schema）与 `docs/agent-ledger.md`。本 skill 与其冲突时以 schema.md 为准。

## 0. 定位数据目录（不硬编码路径）

按顺序解析，找到即停：

1. 环境变量 `POINTS_DATA_DIR`；
2. 项目根 `config.local.json` 的 `dataDir` 字段；
3. 都没有 → 停下，让用户配置（Windows 参考如 `D:\Nutstore\积分商城数据`），**不要猜路径**。

写账前先读 `tasks.json`（档位与常见事项）和 `shop.json`（商品）。改账 / 核销 / 回收前先扫 `ledger/` 找到目标记录。

## 1. 意图分流

| 用户意图 | type | points | exp | ref |
|---|---|---|---|---|
| 记账 / 补记（「刷了牙」「作业写完了」） | `earn` | +分值 | +等量分值 | — |
| 改账（「刚才那条记错了，应该是 20 分」） | `adjust` | 差额 | 差额 | 原记录 id |
| 撤销（「刚才那条不算」） | `adjust` | −原值（全额冲正） | −原值 | 原记录 id |
| 兑换实物（「换杯奶茶」） | `redeem_physical` | −⌈yuan×20⌉ | 0 | —（记 `rate: 20`） |
| 兑换虚拟券（「买张赖床券」） | `redeem_voucher` | −商品定价 | 0 | — |
| 核销（「用掉赖床券」） | `use_voucher` | 0 | 0 | 原兑换记录 id |
| 回收（「赖床券退了吧」） | `recycle_voucher` | +⌊实付×0.8⌋ | 0 | 原兑换记录 id |
| 查询（「多少分 / 几级了」） | 不写账 | 汇总流水后直接回报 | | |

- 核销 / 回收只能作用于**未被核销或回收过**的 `redeem_voucher` 记录（先检查 ref 是否已被引用）。
- 改账**永不覆盖或删除**历史文件，只追加 `adjust` 记录。

## 2. 定分规则（灵活档位制）

1. **常见重复事项**：`tasks.json` 里有固定分值的，直接用（如刷牙 5、上课 10），不做二次判断。同一事项本次与历史流水的分值明显不一致时提醒用户。
2. **其他事项**：不强制套档位，按实际工作量灵活定分；档位表（5/10/20/50/100/200）只作锚点参考。
3. **Jev + 模型共同判断**：对无固定分值的事项——
   - 主模型先给出建议分值和理由；
   - 调用 **Jev**（typesafe-ai 技能的 Jev 模型）对同一事项独立给一个建议分值，附上档位表和该事项近期流水作参照；
   - 两者相差 **≤ 50%**（以较小者为分母）→ 通过，取两者**平均值**（四舍五入到整数）；
   - 相差 **> 50%** → **重新审计**：把对方理由发给两边再各判一次；
     - 第二轮相差 ≤ 50% → 取平均，`note` 里注明「经重审计」；
     - 仍 > 50% → 停下，把两个分值和理由摆给用户定夺，**不要擅自写入**。
   - Jev 不可用（调用失败/无此环境）→ 主模型自行定档，`note` 标注「未经 Jev 复核」。
4. 无论哪种定分，`note` 必须写清**定分理由 / 工作量**，便于复盘。

## 3. 写入（原子性）

1. 生成 id：`YYYYMMDD-HHmmss-xxxx`（末 4 位随机）；`time` 用带时区的 ISO 8601 当前时间。
2. 路径：`<数据目录>/ledger/<YYYY-MM>/<id>.json`。
3. **先写 `<id>.json.tmp`，再改名**为 `<id>.json`——绝不允许直接写最终文件名。
4. 字段：`id, time, type, title, points, exp` 必填；`ref / rate / note` 按需。schema 见 docs/schema.md。
5. 写账前注意同步：若最新流水的 `time` 距今异常久（比如超过上次使用间隔），提醒用户先等坚果云同步完成再确认。

## 4. 回报格式（每次写账后必须回报）

```
✅ 记账成功：刷牙 +5 分（+5 经验）
当前余额 1,240 分 ≈ ¥62 ｜ Lv.6（42/110，还差 80 经验升级）
```

- 余额 = 全部流水 points 之和；经验 = 全部流水 exp 之和；等级按升级公式累减。
- 改账 / 撤销要额外说明原记录和冲正金额；兑换要说明价格换算（`¥15 × 20 = 300 分`）。
- 重新审计后写入的，注明两个判断值与最终取值。

## 5. 红线

- 不删改任何已存在的流水文件。
- 未配置数据目录时不要写入项目目录凑合。
- Jev 与主模型分歧 >50% 且重审计仍分歧时，必须问用户。
