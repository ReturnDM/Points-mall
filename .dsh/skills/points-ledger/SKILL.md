# 积分商城记账（points-ledger）

把用户的一句话变成一条流水，并回报积分与升级进度。**网页是只读的，你是唯一写入方；
写入必须通过项目 CLI `scripts/ledger.mjs`，禁止手写 JSON 文件**（schema 校验 / id 生成 /
原子写 / ref 完整性都已在 CLI 里固化）。完整规则：`docs/schema.md`。

## 0. 前置

1. 定位数据目录：环境变量 `POINTS_DATA_DIR` → 项目根 `config.local.json` 的 `dataDir` → 都没有则让用户配置，**不要猜路径**。CLI 自己会做这个解析。
2. 在项目根 `E:\生活积分商城` 下执行：`node scripts/ledger.mjs <命令>`（或 `npm run ledger -- <命令>`）。
3. 记账前可 `list --limit 10` 和 `summary` 了解近况；改账/核销/回收前先 `list` 找到目标 id。

## 1. 命令 = 意图

| 用户意图 | 命令 |
|---|---|
| 记账 / 补记（「刷了牙」「作业写完了」） | `earn "<事项>" <分值> --note "<定分理由>"` |
| 改账（「那条应该是 20 分」） | `adjust --ref <id> --points <Δ> --exp <Δ> --note "..."` |
| 撤销（「那条不算」） | `adjust --ref <id> --note "..."`（不带 Δ 即全额冲正） |
| 兑换商品（「换杯奶茶」「买张赖床券」） | `redeem <itemId> --note "..."`（实物自动 ⌈yuan×20⌉ 并记 rate；券自动入背包） |
| 核销（「用掉赖床券」） | `use <redeemId>` |
| 回收（「券退了吧」） | `recycle <redeemId>`（自动返还原实付 80%，向下取整，不加经验） |
| 查询（「多少分 / 几级了」） | `summary` |

CLI 每次写账后自动输出回报行（余额 / 等级 / 背包），**原样转述给用户**，不要自己重算。

## 2. 定分规则（灵活档位制）

1. **常见重复事项**：`tasks.json` 固定分值直接用（如刷牙 5、上课 10），不做二次判断；与历史流水明显不一致时提醒用户。
2. **其他事项**：不强制套档位，按实际工作量灵活定分；档位表（5/10/20/50/100/200）只作锚点。
3. **Jev + 模型共同判断**：对无固定分值的事项——
   - 主模型先给建议分值和理由；
   - 调用 **Jev**（typesafe-ai 技能）独立给一个建议分值（附档位表和近期流水作参照）；
   - 相差 **≤ 50%**（以较小者为分母）→ 取**平均值**（四舍五入）写入；
   - 相差 **> 50%** → **重新审计**：把对方理由发给两边再各判一次；仍 > 50% → 停下把两个分值和理由摆给用户定夺，**不要写入**。
   - Jev 不可用 → 主模型自行定档，note 标注「未经 Jev 复核」。
4. `--note` 必写**定分理由 / 工作量**。

## 3. 回报格式

CLI 输出即回报（示例）：

```
✅ 记账成功：刷牙 +5 分（+5 经验）
✅ 余额 1240 分 ≈ ¥62.00 ｜ Lv.6（42/110，还差 80 经验升级）｜ 累计经验 1240 ｜ 背包 0 张券
```

改账 / 撤销额外向用户说明冲正对象与金额；重新审计后写入的，注明两个判断值与最终取值。

## 4. 红线

- **禁止绕过 CLI 手写/删除/修改任何流水文件**（CLI 故障时停下报告，不要用脚本凑合）。
- CLI 报错（ref 不存在、券已核销、商品不存在等）就把错误原文转给用户并停住，不要重试变体。
- Jev 与模型分歧 >50% 且重审计仍分歧时，必须问用户。
- 写账前若最新流水 `time` 距今异常久（比如超过上次使用间隔），提醒先等坚果云同步完成。
